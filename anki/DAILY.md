# Daily deck growth — procedure for the scheduled task

Deck: **Pediatric Hepatology — Landmark Studies** (`anki/Pediatric_Hepatology_Landmark_Studies.apkg`).
Andrey downloads the latest `.apkg` from GitHub whenever he likes and imports it into Anki.
Re-import must never lose his review history, so the rules below about IDs are strict.

Each run adds **2 new studies** (≈2–3 cards each) and **6 extra questions** (1 card each) → ~10–12 new cards per day.

## 0. Setup

- Work in the `reading-final` clone. `pip install --break-system-packages genanki`.
- The shell cannot reach PubMed/NCBI. Get PubMed data with **WebSearch** (`allowed_domains: ["pubmed.ncbi.nlm.nih.gov"]`) and then **WebFetch** of the `https://pubmed.ncbi.nlm.nih.gov/<PMID>/` URL that the search returned.
- Read 3–4 existing cards in `work/cards_*.py` and the last entries of `work/extra_questions.py` / `work/new_studies.py` first, and match their style exactly: short English, one fact per card, `<b>…</b>` around the key figure.

## 1. Pick the focus

- Current lesson = highest `BB-DD` file in `hepatology/`. Focus blocks = that block and the next one.
- Block titles are in `BLOCKS` in `build_landmark_deck.py` (26 blocks of the Hepatology year plan).
- Alternate: on even days of the month take the 2 new studies from the focus blocks; on odd days from the blocks with the fewest studies published ≥2023 (count from `Pediatric_Hepatology_Landmark_Studies_index.csv`). Extra questions: 3 from focus blocks, 3 from any block, oldest-added studies first.

## 2. Two new studies → `work/new_studies.py`

What qualifies (in this priority): RCTs and phase 3 trials; large multicenter/registry cohorts that changed practice or define natural history; meta-analyses; new society guidelines/practice statements (AASLD, NASPGHAN, ESPGHAN, EASL, AST/ILTS/SPLIT). Pediatric first; adult studies only if they directly change pediatric practice (tag `adult`). Prefer **published in the last 24 months**. No case reports, small single-center series, narrative reviews, letters or conference abstracts.

For each candidate:

1. Not already present: grep the PMID and the trial name in `work/abstracts.json`, `Pediatric_Hepatology_Landmark_Studies_index.csv`, `work/new_studies.py`.
2. WebFetch the PubMed page and ask for: title, journal (NLM abbreviation), year, first author as written ("Schwimmer JB"), whether there are more authors, DOI, and the **full abstract verbatim**.
   If you cannot get the full abstract, **skip the study** and pick another.
3. Save that as JSON with the Write tool and run `python3 work/add_abstract.py <file.json>` (`topic` = short block keyword).
4. Append a dict to `NEW` in `work/new_studies.py`:
   - `pmid`, `deck="NN <Block title>"`, `name` (trial acronym, or "Topic (FirstAuthor Year)"), `q` (the clinical question the study answers), `design` (design, n, population, intervention/comparator, duration), `result` (primary outcome with real numbers; ONE key figure in `<b>…</b>`), `bottom` (what to do with it, plus the main caveat), `tags` (topic words + design: `rct` / `trial` / `meta` / `cohort` / `guideline`; `adult` or `mixed` if not purely pediatric; `harm` or `negative` when true),
   - `answer` (one line for the Question card), `stat=("value", "caption")` or `None`, `named=True` only if the study has a recognised name/acronym, `added="YYYY-MM-DD"` (today, America/New_York).
   - Every number must appear in the abstract you stored. Never invent or round beyond the abstract.

## 3. Six extra questions → `work/extra_questions.py`

Extra notes on studies already in the deck, each testing a **different** fact than the study's existing Question / Key-number cards. Good types:
- design & population ("n, who, comparator, dose?"),
- a secondary result or a subgroup,
- a harm / adverse-event figure,
- a short clinical scenario where the study decides what you do,
- the main limitation (e.g. external control, small n, adult data).

Rules: facts only from that study's `design`/`result`/`bottom` text or its stored abstract; answer ≤ 25 words with one `<b>` figure; at most 3 extra questions per study in total; `key` = short, unique per PMID, **never changed after release** (it is part of the note GUID); `added` = today.

## 4. Build and check

- `python3 build_landmark_deck.py` — it asserts no duplicate PMIDs/keys and that every extra question points to a real study. The printed totals must be higher than before the run by what you added.
- Never edit or delete existing cards, `MODEL_ID`, field order, deck names or GUID rules. Corrections to an existing card's wording are allowed only for a factual error, and must be listed in the commit message.
- `CHANGELOG.md` is regenerated by the build.

## 5. Commit

Commit `anki/` (apkg, csv, CHANGELOG.md, work/*.py, work/abstracts.json) with message `Anki +N cards (YYYY-MM-DD): <study names>`, then fetch/rebase/push to `main` (same one-command-per-call git rule as the lesson task).
